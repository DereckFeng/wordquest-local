# WordQuest Local

一个面向家庭或小型局域网的英语听写练习站。它把“课程导入、逐句听写、错词复习、拼写游戏、本地账号和学习进度”放在同一台主机上运行。

本仓库是**仅代码版本**：不包含任何课程 PDF、课程正文、课程标题清单、原始录音、音频切片、语音模型、OCR/ASR 结果、学生账号或学习记录。使用者必须自行准备并确认有权使用的内容。

> RAZ、Reading A-Z 及相关内容属于其各自权利人。本项目与其权利人无隶属、授权或背书关系。

## 能做什么

- 通过 CSV 或 JSON 导入使用者自己的课程包，英文原文按原值保存。
- 按句播放音频，并按单词提供字母数量提示。
- 听写判定区分大小写；标点显示但不要求输入。
- 连续拼错的词自动进入当前学生的单词本。
- 提供单词复习和一局八层的拼写远征游戏。
- 使用本地用户名和密码登录，账号与进度按学生隔离。
- 优先使用已经过质量检查的逐句录音；缺失时回退到统一 TTS，再失败才使用浏览器语音。
- 附带 PDF 文本提取、扫描页 OCR、音频匹配、时间对齐、批量切分和质量检查工具。

## 技术结构

| 层 | 实现 |
| --- | --- |
| Web 界面 | React 19、Next.js App Router、TypeScript、CSS |
| 本地运行 | vinext、Vite、Cloudflare Worker 本地运行时 |
| 数据库 | D1/SQLite、Drizzle schema |
| 账号安全 | PBKDF2-SHA-256 加盐哈希、HttpOnly Cookie、本地会话 |

## 快速开始

要求：

- Node.js 22.13 或更新版本
- npm
- Python 3（用于统一 TTS 和离线处理工具）

安装并检查：

```bash
npm install
npm test
```

本机启动：

```bash
npm run dev
```

同一局域网访问：

```bash
npm run dev:lan
```

终端会显示主机地址。主机需要保持运行；本地 D1 数据保存在被忽略的 `.wrangler/` 中，部署或迁移前请单独备份。

### 可选：统一 TTS

安装本地模型与 Python 环境：

```bash
zsh scripts/install_tts_model.sh
```

生成过的 WAV 会缓存到 `.tts-cache/`。模型、虚拟环境和缓存都不会进入 Git。

若没有模型，macOS 主机可使用系统语音提供统一发音。其他系统应安装 Kokoro 运行依赖，或自行替换 `scripts/tts_server.py` 中的语音后端。

## 导入自己的课程

仓库不提供示例课文。课程只能从你有权使用的本地文件导入。

CSV 表头：

```csv
level,lesson_id,lesson_title,lesson_title_zh,sentence_id,english,chinese
```

JSON 可以直接使用课程数组，或使用带 `lessons` 字段的对象：

```json
{
  "lessons": [
    {
      "id": "<LESSON_ID>",
      "level": "<LEVEL>",
      "title": "<TITLE>",
      "titleZh": "",
      "sentences": [
        {
          "id": "<SENTENCE_ID>",
          "english": "<AUTHORIZED_TEXT>",
          "chinese": ""
        }
      ]
    }
  ]
}
```

导入器要求 `level`、课程 ID、标题和英文句子存在。CSV 中含逗号的字段应使用标准双引号转义。课程包写入本地数据库后，不需要放进项目源码目录。

git status --short

## PDF 文本提取：本项目的经验

### 1. 先做清点，不要直接批量抽取

第一步应记录每个 PDF 的页数、纸张方向、页面尺寸、文字层覆盖率和异常页。带文字层与纯扫描 PDF 是两条不同管线；把两者混在一起处理，会让失败看起来像“少量乱码”，实际上可能整本都不可用。

`scripts/analyze_raz_pdfs.py` 用于做基础清点。经验上应先抽取少量代表样本，确认版式规律，再扩大批次。

### 2. 物理页不等于阅读页

教材 PDF 常见两种拼版：

- 横向物理页包含左、右两个正向逻辑页；
- 纵向物理页包含上方正向页和下方旋转 180° 的逻辑页。

可靠做法是根据页面宽高判断拼版方式，裁成逻辑页，给倒置页同时转换文字方向和坐标，再按“逻辑页、行、横向位置”重建阅读顺序。只使用 `extract_text()` 的自然顺序，容易把两栏、上下页或页脚交叉拼接。

### 3. 用版面特征找正文

正文识别不能只靠固定裁剪框。本项目结合：

- 全书主导字号；
- 主导字体家族；
- 行的纵向位置；
- 句末标点；
- 粗体标题特征；
- 页码、网址、目录点线和前后附录标记；
- 双栏页面中的大横向间距。

这样比“删除前两页和最后两页”更稳，因为不同版本的封面、目录、活动页和术语表页数并不一致。字体名可能带子集前缀或 Bold/Italic 后缀，比较前应先归一化字体家族。

### 4. 文本归一化必须保守

可以安全处理的通常包括 Unicode NFC、软连字符、连续空白和标点前后的异常空格。不要让 OCR 或语言模型“润色”正文，也不要用识别结果覆盖授权原文。

分句前要保护缩写、小数、首字母缩写和引号内句末标点，否则 `Mr.`、小数点或首字母会被误当成句子边界。清理后的每句话仍应保留原有大小写和标点。

### 5. 扫描页要交叉验证

纯扫描页的建议流程：

1. 以稳定 DPI 渲染页面；
2. 使用第一套 OCR 得到正文与坐标；
3. 用第二套独立 OCR 复核；
4. 只把两者不一致的页面送入人工或视觉模型复核；
5. 保存页图、两个候选结果、最终选择和证据；
6. 对已经复核的结果做缓存，断点续跑时不重复调用模型。

OCR 提示词应要求“只抄录正文、忽略页码/图注/标签、保留大小写和标点”，但模型输出仍然只是候选，不是自动真值。

### 6. QA 比抽取算法更重要

每课至少检查：

- 是否有正文、句子和唯一 ID；
- 是否混入目录、网址、页码、图注或模型解释语；
- 是否存在异常长句、缺失句末标点或替换字符；
- 封面标注词数与抽取词数的差异；
- 每个逻辑页抽取了什么、为何跳过；
- 源文件大小、修改时间和提取器版本是否与缓存一致。

不要让“程序成功退出”等同于“内容正确”。有疑点的课应进入 review 集合，而不是混进可直接导入的集合。

### 7. 修订规则应作为私有数据

少量人工确认的正文修订不应硬编码在公开程序中。`scripts/repair_raz_verified_text.py` 改为读取外部 JSON：

```json
{
  "corrections": [
    {
      "level": "<LEVEL>",
      "title": "<TITLE>",
      "replace": "<EXACT_OLD_TEXT>",
      "with": ["<EXACT_NEW_TEXT>"],
      "evidence": "<WHERE_IT_WAS_VERIFIED>"
    }
  ]
}
```

调用：

```bash
python scripts/repair_raz_verified_text.py \
  --corrections /path/to/private-corrections.json \
  /path/to/private-extraction.json
```

课程排序同理。`scripts/build_raz_course_library.py --order-map` 可读取私有 JSON 映射，公开代码不保存课程标题清单。

## 音频切分：本项目的经验

### 1. 先保守匹配“课”和“录音”

文件名与课程标题通常并不完全一致。匹配前应做 Unicode 归一化、去编号、大小写折叠、标点清理和 token 化，再综合字符相似度、token 相似度和包含关系。

只看最高分不够：还要检查第一名与第二名的差距，并保证一份音频不会自动分配给两课。低分或歧义项应拒绝自动匹配，允许在私有映射文件中人工覆盖。

### 2. 原文和 ASR 的职责必须分开

授权原文是不可变参考；ASR 只提供声学时间锚点。推荐流程：

1. 将原文规范化成词序列；
2. 用 faster-whisper 获取带概率的逐词时间戳；
3. 使用半全局动态规划把原文词与识别词对齐；
4. 允许录音开头和结尾存在书名、作者或说明语；
5. 如果任何句子没有可用锚点，整课失败，不猜测时间。

半全局对齐比逐句独立搜索更能保持全课顺序，也能容忍少量漏词、插词和近似识别。

### 3. 让静音修正边界，不要让静音决定内容

FFmpeg `silencedetect` 可以找到停顿，但短停顿不一定是句界，长停顿也可能出现在句内。更稳的做法是先用词时间戳确定句子的首末锚点，再把边界在很小窗口内吸附到附近静音中点。

切片应允许句间保留空隙。把所有音频无缝分给相邻两句，会把书名、图注、问题或版本差异的额外旁白硬塞进某个句子。只有相邻切片真正重叠时，才在两个声学锚点之间取中点解冲突。

### 4. 需要多条对齐路径

- **faster-whisper**：速度较快，适合大多数有清楚时间锚点的录音。
- **stable-ts 强制对齐**：直接把不可修改的原文对齐到音频，适合普通 ASR 漏锚点的情况。
- **更大模型找锚点 + 小模型独立验收**：适合困难样本；生成候选和验收不要使用同一个模型。
- **MFA**：适合在已有粗边界附近进一步收窄少量高风险窗口，不适合盲目替代整个主流程。

无论哪条路径，零时长、极低概率或缺失锚点都应失败并进入隔离区。

### 5. 切完必须重新听一次（机器也一样）

对切出的 MP3 再做独立 ASR，比较“切片识别文本”和“目标句规范化文本”。除整体相似度外，还要检查它是否更像前一句或后一句，以发现串句。

本项目使用的质量信号包括：

- 原文词覆盖率；
- 单句匹配比例与平均词概率；
- 低置信切片比例；
- 过短或过长切片；
- 切后独立识别得分；
- 相邻句污染；
- 句子数量、文件数量和索引数量是否一致。

阈值应在代表样本上校准，并宁可拒绝，也不要把可疑切片发布给学习者。

### 6. 发布必须是原子的、可恢复的

批处理先写 staging，全部检查通过后再移动到正式目录。失败项写入 rejected 目录和结构化报告，并从正式索引中移除旧入口。

长批次要做到：

- 每课完成后立即原子写入状态和索引；
- 临时文件写完后再 `replace`，防止中断留下半个 JSON；
- 支持断点续跑、跳过已完成项和显式强制重跑；
- 不同分片使用不同 state/index，最后再合并；
- 合并时清理失败课程的陈旧索引；
- 外部 ASR 在正式改动前先用短音频做能力预检。

“生成了文件”不代表“可以发布”；staging、validation、promotion 三个阶段应明确分开。

## 本次 vibecoding 的经验总结

### 从模糊目标到可验证规则

“做一个听写游戏”过于宽泛。真正推动实现的是把目标改写成可检查的规则：何时自动跳到下一词、大小写是否敏感、标点是否参与判定、错几次揭示答案、进度属于谁、音频失败如何回退。每条规则都应该能映射到状态、界面反馈和测试。

### 先划数据边界，再写功能

这个项目最大的风险不是 UI，而是课程内容、音频、模型和学生数据混在代码目录中。越早确定“源码可公开、内容只在本地、生成物可重建、账号数据可备份”的边界，后续越不容易误上传或把部署和内容绑定死。

### 本地优先不等于浏览器优先

把进度存在浏览器会导致换设备丢失、多人互相覆盖。局域网应用更适合由主机维护账号、课程库和进度，浏览器只保存 HttpOnly 会话 Cookie。这样既保持本地化，也能支持多个学生设备。

### 回退链必须可见

原版逐句录音、服务器统一 TTS、浏览器临时语音是三种质量不同的来源。回退不能静默发生，界面要告诉使用者当前听到的是什么，否则同一练习可能在不同设备上出现无法解释的声音差异。

### 批处理要把失败当成正常状态

PDF、OCR、ASR 和音频版本差异决定了“全量一次成功”不现实。好的批处理不是没有失败，而是能定位失败、保存证据、不中断其他任务、重跑指定子集，并保证失败结果不会污染正式索引。

### 用独立证据验收模型输出

同一个模型既生成时间边界又验收自己的切片，容易重复同一种错误。困难音频应使用不同模型或不同方法交叉验证；扫描页也应使用第二 OCR 或人工证据复核争议项。

### 原子写入和隔离目录很值钱

长任务最怕中断后不知道哪些结果可信。临时写入、原子替换、staging、rejected、逐项状态文件和可重复的 manifest，让数小时或数天的任务可以安全恢复。

### 缓存必须带来源指纹和算法版本

只按文件名缓存会在源 PDF 更新或提取器修正后复用旧错误。缓存至少记录路径、文件大小、修改时间和提取器版本；模型、阈值或归一化规则变化时也应使缓存失效。

### 测试应该验证契约，不要依赖私有内容

公开测试不能要求某本课程、某句话或某个音频 ID 存在。它应验证导入格式、鉴权、状态隔离、回退逻辑、质量门槛和版权目录确实被忽略。私有内容的端到端检查应留在本地 QA 流程。

### AI 适合加速探索，但决策需要留痕

vibecoding 很适合快速搭界面、补脚本和比较方案，但以下内容不能只靠“看起来正确”：

- 鉴权和会话安全；
- 教材原文是否被改写；
- 音频是否切到相邻句；
- 批量处理是否能恢复；
- 公开仓库是否真的没有私有内容。

关键决策最好固化为代码中的门槛、结构化报告、测试和 README，而不是只留在聊天记录里。

## 常用命令

```bash
# Web 构建与测试
npm test

# 安装音频对齐环境（模型和环境均被忽略）
zsh scripts/install_audio_alignment.sh

python scripts/build_raz_audio_catalog.py \
  --library /path/to/private-course-library.json \
  --audio-root /path/to/authorized-audio \
  --output tmp/private-audio-catalog.json

# 切分单课；占位符必须替换为本地授权内容
./.audio-venv/bin/python scripts/segment_raz_audio.py \
  --lesson-id <LESSON_ID> \
  --audio /path/to/authorized-audio.mp3 \
  --library /path/to/private-course-library.json \
  --output tmp/private-clips/<LESSON_ID> \
  --url-prefix /raz-audio/<LEVEL>/<LESSON_ID> \
  --index tmp/private-audio-index.json
```

先在少量代表样本上验证，再启动全量批处理。

## 安全与限制

- 当前设计面向可信局域网，不建议直接暴露到公网。
- Cookie 使用 `HttpOnly` 和 `SameSite=Lax`；若部署到 HTTPS 公网，还应启用 `Secure`、CSRF 防护、登录限速和更严格的安全头。
- TTS 服务默认监听局域网地址并允许跨域访问，适合本地课堂，不适合无防火墙的公网主机。
- 本仓库提供工具链，不提供课程或录音的使用授权。
- 在处理儿童账号和学习记录时，应遵守所在地区的隐私与数据保护要求。
